# 可机械验证的步骤做成脚本，不写成散文

正文提到「读 PDF 附件」「核验文号」时，指向 `scripts/read_pdf.py` 与 `scripts/check_wenhao.py`，不写成「用 pypdf 读一下」这类散文指令。理由是散文指令要求每次会话重新实现一遍，而这两件事的失败都很安静：PDF 的 `/Filter` 是过滤链时只解一层会让 zlib 报 `incorrect header check` 并返回空，`/Resources` 里的 `/Font` 指向的是字体名字典而不是字体字典本身——读出来是空的，却看起来像「这份文件没有文字层」。对照组里技能版输给无技能版，正是输在这条通路上：无技能版自己写了解析器，技能版按纪律降级了。代价是多两份要维护的代码，且脚本自带后端的能力边界（无文字层、加密 PDF）必须写明，否则空结果会被误读成不存在。
