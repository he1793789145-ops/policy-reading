# policy-reading

一个给 AI agent 用的政策判读技能（skill）：从一手政策信息里判断一个方向**是被推进还是被收紧**、有没有**真金白银和具体项目**，最后折算成普通人可行动的岗位或生意。

不是政策资讯聚合，不是自媒体解读。产物是一份**可对质**的判读——每条关键结论都带文号、发布机关、发布日期、原文链接和逐字原句。

## 为什么需要它

政策回答的是"资源往哪里配"，不是"进去就一定赚钱"。

直接问 AI「XX 方向有没有机会」，通常得到的是没有出处的乐观结论：方向词被放大，资金与项目被省略，你没法核对任何一句。这个技能把这件事拆成八步，每一步以完成标准收尾，并要求四类判断（资金、项目、实施方案、限制信号）必须带逐字原句——**没有出处的话不许出现在证据表里**。

## 它做什么

默认走全流程八步：

| # | 步骤 | 完成标准 |
|---|---|---|
| 1 | 定轨：类别（就业/创业/投资）、所在地、已有能力与资源 | 三项有答案，或明确记"未知"并标注结论未按条件校验 |
| 2 | 立检索面 | 入口落到具体 URL，标注能读到什么（全文/仅标题/读不到） |
| 3 | 成对取原文与官方解读 | 每个关键判断背后既有原文链接也有解读链接 |
| 4 | 判读三类表述 | 每条判断带文号＋机关＋日期＋链接＋逐字原句 |
| 5 | 落三问、拉跨年表、定三档 | 逐年标注资金/项目/方案，连续 ≥3 年只有概念标"概念空转" |
| 6 | 折算到产业链环节 | 每个环节能追到至少一份文件的具体表述 |
| 7 | 机会与限制成对输出 | 没有落单的机会 |
| 8 | 低成本验证与观察清单 | 一周内、千元内、必须触达真实潜在客户 |

也可以只走局部：

- **只判读**（"我只想看懂这份文件"）→ 第 3–4 步，可加第 5 步
- **只有概念**（"这个方向怎么样"）→ 第 2–5 步

跳过的步骤会明确告诉你，并说明哪些结论因此不可靠。

## 三条硬纪律

这三个约束是设计上的取舍，不是装饰：

1. **机会必须与限制信号成对。** 任何一条"机会"旁边都跟着它的限制条件。只报喜的判读会让人误判风险。
2. **查不到就写查不到。** 读不到的文件、核不实的文号，写进「证据不足」，档位记"不确定"。**查不到不得默认成有**。
3. **投资轨只给方向。** 不出标的、不给买卖时点、不估收益——这套方法的证据是政策文本与官方数据，它撑得起"什么需求会变大"，撑不起定价与择时。

详见 [ADR-0003](docs/adr/0003-three-tier-landing-not-scores.md)、[ADR-0004](docs/adr/0004-investment-track-direction-only.md)。

## 安装

把 `skill/` 目录复制到你的技能根目录，重命名为 `policy-reading`：

```
<技能根目录>/
└── policy-reading/
    ├── SKILL.md
    └── references/
        ├── method.md
        ├── judging.md
        ├── sources.md
        └── report.md
```

常见技能根目录：

- Windows：`%USERPROFILE%\.dsh\skills\`
- macOS / Linux：`~/.dsh/skills/`

`SKILL.md` 必须在 `policy-reading/` 里**直接一层**，不要多套一层目录。

重启或新开会话后验证：输入 `/policy-reading`，或直接问「十五五里有没有跟我行业相关的机会」看它会不会自动接手。

> **安装不上时**：已知有环境里技能根的扫描在会话启动时定下来、之后不重算——技能是好的，只是那个会话看不见它。判断方法：新开一个会话再试。新会话能用，说明是旧会话的问题。

## 使用建议

**给它一个具体身份和地点**，质量差别很大：

```
我在县城做家电维修，想看看十五五规划里有没有跟我相关的机会
```

比「十五五有什么机会」有用得多。因为第 1 步要的类别、所在地、已有能力它不知道，就只能给通用结论，并在报告里标注"未按你的条件校验"。

**手上有文件就直接给**，比让它自己检索更准：

```
帮我读一下这份《XX 管理办法》征求意见稿，对我做 XX 有什么影响
```

## 评测：它到底比不用强多少

这个仓库带三组 **with / without 对照**（`evals/`），任务原文完全相同，唯一差别是给不给技能。三条 prompt 各打一条不同分支：

| 用例 | prompt | 观察到什么 |
|---|---|---|
| [eval-0](evals/iteration-1/eval-0-county-appliance/) | 县城家电维修，十五五有没有机会 | **技能赢在可对质**：给了三份地方原文把"维修"直接写进中央财政资金支持方向，抓到反向信号（品类从 12 类收窄回 6 类、门槛抬到 1 级能效、单件上限 2000→1500 元） |
| [eval-1](evals/iteration-1/eval-1-miit-design-draft/) | 工信部《工业设计中心管理办法》征求意见稿对外包的影响 | **技能输了**：无技能那份自己写了 PDF 提取器读到全文；有技能那份在 PDF 通路上全面失败，严格按"查不到就写查不到"把条款记成"不确定"——没编，但把用户的真问题留成了空洞 |
| [eval-2](evals/iteration-1/eval-2-eldercare-quit/) | 都说养老是蓝海，要不要辞职去干 | **技能赢在证据与双向性**：拿到了资金侧文号和最关键的反向信号（国办函〔2026〕14号要求"关停并转、有序退出"） |

**这份评测最有价值的部分是 eval-1。**

它暴露了一个真实缺陷：技能当时假定"捆绑 Python 无 PDF 库，只能手工解 FlateDecode"，因此放弃了 pypdf 这条一行通路。修订后做了[定向复验](evals/iteration-2/eval-1-miit-design-draft/)——同样的 prompt、同样的技能、**不给任何关于 PDF 的提示**，这一轮读出了征求意见稿全文（18 条＋附表门槛），而上一轮是"正文读不到、全记不确定"。

差异只来自那一处修订。这条留在仓库里，是因为**一个只说优点的评测没有信息量**。

另外三条 with_skill 报告都主动申报了自己跳过的步骤与降级的证据——这是行为层面最明显的改变。

## 设计记录

- **[CONTEXT.md](CONTEXT.md)** — 22 个术语的 glossary（政策机会、落地、概念空转、预期窗口、承重行、低成本验证…）。每个术语带 `_Avoid_` 行，明确**不该用哪些词**（比如"政策机会"不能用"风口""蓝海"代替）。
- **5 条 ADR** — 每条记录一个难以逆转的决定与它的代价：
  - [0001](docs/adr/0001-process-in-skill-method-out-of-body.md) 流程进 SKILL.md，方法论不进常驻正文
  - [0002](docs/adr/0002-sources-national-explicit-local-locator.md) 源清单：国家级写实到栏目，地方只给定位法
  - [0003](docs/adr/0003-three-tier-landing-not-scores.md) 落地程度用三档判定，不用分数
  - [0004](docs/adr/0004-investment-track-direction-only.md) 投资轨只给方向，不给标的
  - [0005](docs/adr/0005-scheduled-tasks-proposed-not-created.md) 自动化任务只提议，由用户决定

## 已知限制

- **依赖非公开接口。** 主检索入口是 `sousuo.www.gov.cn/search-gov/data`，今天能用、官方不承诺、随时可能失效。失效时退回"请用户贴原文"。详见 [references/sources.md](skill/references/sources.md)。
- **地方站点的可读性差异很大。** 部分地方政府门户的列表页是 JS 渲染，读不到；县级站点覆盖尤其不稳定。
- **征求意见稿没有全国统一聚合页**，只能按部委分别采。
- **评测是定性的**，不是 benchmark。三组对照用来暴露缺陷、校准描述，不用来给技能打分。
